# Provenance and contribution boundary

The runtime source was exported from Git commit
`8b473d8424df5b1b7f006a6bc252858f0647a28e` without changing the original checkout.
`metadata/source-files.json` gives SHA256, original Git blob SHA1, file mode and
path for each preserved source file. `scripts/check_source.py` checks them.
The only excluded original file is the operational migration diary; its
replacement explains the exclusion. Original compute code is not reformatted.

`data/contribution-provenance.json` separates inherited model/graph/operator
capabilities from documented route, VJP, graph-consumer, normalizer and output
changes. A recorded enablement commit is not proof of original invention or
personal authorship. The maintainer listed here is not claimed to be the author
of every included upstream file.

The selected source commit, measured engine, chain, Python core, native backend,
model and image have different identities. See `data/frozen-version.json`.
The Python package additionally carries its original per-file lock. Post-link
transforms and build paths can affect rebuilt native identities; no equivalence
of a future rebuild to the recorded binary is claimed here.

Historical docs inside the runtime directory retain their historical wording;
references to validation there are past project records, not tests executed
during this repository preparation. No later NVIDIA prototype is mixed into the
PPU score. All new packaging files are outside the historical compute paths.

Generative AI tools assisted implementation, analysis and preparation during the
project. Human authors and maintainers are responsible for checking the released
code, attribution, results and manuscript. The precise manuscript disclosure
should match the authors' final account of tool use.
